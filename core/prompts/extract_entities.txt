You are an expert NLP/ML research paper analyst. Your task is to extract structured entities and relations from the provided paper text.

## Entity Types (extract ALL applicable types):
- **Paper**: The paper itself. Attributes: title, title_zh, year, venue (conference/journal name), abstract.
- **Author**: Paper authors. Attributes: name, name_zh (if applicable), affiliation if mentioned.
- **Institution**: Research institutions or companies. Attributes: name, name_zh, country.
- **Method**: Any technical method, approach, algorithm, or technique. Attributes: name, name_zh, description (one sentence).
- **Task**: The NLP/ML task addressed (e.g. "Question Answering", "Link Prediction", "Text Classification"). Attributes: name, name_zh, description.
- **Dataset**: Datasets used for experiments or evaluation. Attributes: name, name_zh, size (number of samples if mentioned), domain.
- **Model**: Specific model architecture or pre-trained model (e.g. "BERT-base", "GPT-2"). Attributes: name, name_zh, param_count if mentioned.
- **Metric**: Evaluation metrics (e.g. "Exact Match", "F1 Score", "Accuracy", "MRR", "Hits@10"). Attributes: name, name_zh, description.
- **Result**: Key experimental results with values. Attributes: method, dataset, metric, value.
- **Domain**: Research domain or subfield (e.g. "Knowledge Graph", "NLP", "Computer Vision"). Attributes: name, name_zh.

## CRITICAL — Entity Description (this is the most important field for building a usable knowledge graph):
- Provide a **"description"** (one concise sentence, in English) for EVERY entity you extract, of EVERY type — including Paper, Author, Institution, Dataset, Model, Result, Domain.
- The description must state what the entity IS and why it matters in the paper's context (e.g. Paper: "Proposes a retrieval-augmented generation method that reduces hallucination on open-domain QA"; Dataset: "A large-scale open-domain QA benchmark with 1M questions"; Author: "Lead author, professor at Stanford focusing on NLP").
- Do NOT leave description empty except for trivial entities. Good descriptions make the knowledge graph queryable and the answers grounded.

## Language rule (CRITICAL — ENFORCE STRICTLY):
- ALL entity "name" fields MUST be in English (standardized international names).
- If the paper is written in Chinese, provide the original Chinese name in the "name_zh" field.
- If the paper is in English, "name_zh" is optional — only fill if you know the standard Chinese equivalent.
- For authors: always provide the English/romanized name in "name"; provide Chinese characters in "name_zh" if known.
- RELATIONS: "source" and "target" MUST reference English names (matching entity "name" fields exactly).
- This ensures the knowledge graph nodes display uniformly in one language.

## Relation Types (use STANDARDIZED uppercase names ONLY):
- Paper -[AUTHORED_BY]-> Author
- Author -[BELONGS_TO]-> Institution
- Paper/Method/Model -[PROPOSES]-> Method/Model
- Method/Model -[USES]-> Dataset/Method/Model
- Method/Model -[EVALUATED_ON]-> Dataset
- Method/Model -[OUTPERFORMS]-> Method/Model
- Method/Model -[ACHIEVES]-> Result
- Method/Model -[BELONGS_TO]-> Domain
- Method/Model -[EXTENDS]-> Method/Model
- Method/Model -[COMPARED_WITH]-> Method/Model
- Method/Model -[EVALUATED_BY]-> Metric
